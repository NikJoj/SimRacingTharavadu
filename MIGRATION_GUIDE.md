# SRT Portal — Migration Guide
## Vercel → Azure Static Web Apps

This document covers the complete migration from Vercel (free tier, 12-function limit)
to Azure Static Web Apps + Azure Functions (free tier, unlimited functions).

---

## Overview of Changes

| What | Before | After |
|---|---|---|
| Hosting | Vercel (Hobby free) | Azure Static Web Apps (Free) |
| Functions | 12 (hit limit) | 14 (no limit) |
| API pattern | Vercel `export default handler(req, res)` | Azure Functions v4 `app.http()` |
| CORS config | `vercel.json` | `staticwebapp.config.json` |
| Race storage | Vercel Blob | Neon PostgreSQL `race_results` table |
| DB | Neon (unchanged) | Neon (unchanged) |
| Poster sync | GitHub API (unchanged) | GitHub API (unchanged) |
| CI/CD | Vercel auto-deploy | GitHub Actions (auto-generated by Azure) |

## Prerequisites

- Azure account at [portal.azure.com](https://portal.azure.com) (free — requires credit card for activation, will NOT be charged on free tier)
- Your code on the `azure` branch of GitHub
- Node.js 18+ installed locally (for running the migration script)
- Neon database already set up with `DATABASE_URL`

---

## Step 1 — Run Blob Data Migration (if you have stored races)

Do this **before** switching hosting, while Vercel Blob is still accessible.

```bash
# Install dependencies temporarily for the migration script
npm install --prefix scripts @neondatabase/serverless @vercel/blob

# Run migration
DATABASE_URL="postgresql://..." BLOB_READ_WRITE_TOKEN="vercel_blob_..." node scripts/migrate-blob-to-neon.js
```

If the output shows `No blob data to migrate`, skip to Step 2.

Verify the data landed in Neon:
```sql
SELECT league, COUNT(*) as races FROM race_results GROUP BY league;
```

---

## Step 2 — Create Azure Static Web App

1. Go to [portal.azure.com](https://portal.azure.com)
2. Click **Create a resource** → search **Static Web App** → click **Create**
3. Fill in:
   - **Subscription**: your subscription
   - **Resource Group**: create new `srt-portal-rg`
   - **Name**: `simracingtharavadu` (or similar)
   - **Plan type**: **Free**
   - **Region**: `East Asia` or `Central India` (closest to your users)
   - **Source**: GitHub
   - **Organization / Repository / Branch**: your repo + `azure` branch
   - **Build Details**:
     - **App location**: `/`
     - **API location**: `api`
     - **Output location**: `/`
4. Click **Review + create** → **Create**

Azure will:
- Add a GitHub Actions workflow file to your repo automatically
- Deploy on every push to the `azure` branch

---

## Step 3 — Configure Environment Variables

In Azure Portal → your Static Web App → **Configuration** → **Application settings**,
add these key-value pairs:

| Key | Value |
|---|---|
| `DATABASE_URL` | `postgresql://neondb_owner:...@...neondb?sslmode=require` |
| `ADMIN_USERNAME` | your admin username |
| `ADMIN_PASSWORD` | your admin password |
| `JWT_SECRET` | random 32-character string |
| `GITHUB_TOKEN` | GitHub PAT with `repo` scope |
| `GITHUB_OWNER` | your GitHub username |
| `GITHUB_REPO` | `SimRacingTharavadu` |
| `GITHUB_BRANCH` | `main` |

> **Do NOT add** `BLOB_READ_WRITE_TOKEN` — it is no longer needed.

## Step 5 — Point Custom Domain to Azure (if applicable)

In Azure Portal → your Static Web App → **Custom domains** → **Add**:
- Add your domain
- Follow the CNAME/TXT DNS instructions provided

Then remove the custom domain from Vercel to avoid DNS conflicts.

---

## Step 6 — Decommission Vercel

Once Azure is verified working:
1. Remove the custom domain from Vercel (if you had one)
2. You can leave the Vercel project in place as a backup, or delete it
3. Revoke `BLOB_READ_WRITE_TOKEN` in Vercel dashboard (Blob storage tab)

---

## Rollback Plan

If Azure has issues, Vercel can be re-enabled immediately:

1. The `main` branch on GitHub still has the original Vercel-compatible code structure at the pre-azure commits
2. In Vercel dashboard, re-link to the `main` branch and redeploy
3. DNS switch back takes ~1 minute (TTL dependent)

## Local Development on Azure

Install [Azure Functions Core Tools](https://learn.microsoft.com/en-us/azure/azure-functions/functions-run-local):

```bash
npm install -g azure-functions-core-tools@4 --unsafe-perm true
```

Create `api/local.settings.json` (do NOT commit this file):
```json
{
  "IsEncrypted": false,
  "Values": {
    "FUNCTIONS_WORKER_RUNTIME": "node",
    "AzureWebJobsStorage": "UseDevelopmentStorage=true",
    "DATABASE_URL": "postgresql://...",
    "ADMIN_USERNAME": "admin",
    "ADMIN_PASSWORD": "...",
    "JWT_SECRET": "...",
    "GITHUB_TOKEN": "...",
    "GITHUB_OWNER": "...",
    "GITHUB_REPO": "SimRacingTharavadu",
    "GITHUB_BRANCH": "main"
  }
}
```

Then run:
```bash
cd api
func start
```

Functions will be available at `http://localhost:7071/api/...`
